## Notes

- The script parses every `resources/js/**/*.vue` with `@vue/compiler-sfc` (already a dependency of `vue`; no new package) and walks the template AST. It fails on `v-html`, and on `v-bind`/`:` with the argument `innerHTML` or `outerHTML`. It also scans `<script>` blocks and `resources/js/**/*.ts` for `innerHTML`, `outerHTML`, `insertAdjacentHTML` and `document.write`.
- Allow-list `scripts/raw-html-allowlist.json`, exactly one entry: `{ "file": "resources/js/components/TwoFactorSetupModal.vue", "expr": "qrCodeSvg", "reason": "Fortify-generated QR SVG, no user input (G1-3)" }`. Matching is on file **and** expression.
- Fixtures (`tests/fixtures/raw-html/`, with `expected.json` listing pass or fail per file): `v-html` fails; `:innerHTML` fails; `v-bind:outerHTML` fails; the allow-listed file and expression pass; a second `v-html` in the allow-listed file fails; `el.innerHTML =` in a script block fails; `insertAdjacentHTML` and `document.write` in a `.ts` file fail; plain `{{ title }}` passes. Test names in `expected.json` start with `CC.AC3` or `T-03`.
- `npm run check:html:fixtures` runs the script in fixture mode against `expected.json`. Both scripts run in the CI `lint` job (T-002).
- If the kit has any other raw-HTML use, stop and escalate: it needs an owner decision, not an allow-list entry.
