## Notes

**Jobs** (ADR-0003 CI gates table; PHP 8.4, Node 26, `npm ci`, `composer install`): `lint`, `js-unit`, `workflow-lint`, `test-sqlite` (coverage 85, then `php tests/coverage-dirs.php build/clover.xml app/Http=90 app/Policies=90`), `mutation`, `test-pgsql` (`services: postgres:18`, every `DB_*` variable plus `EXPECTED_DB_DRIVER=pgsql`, `EXPECTED_DB_DATABASE=testing`), `browser-chromium` (installs Chromium with Playwright; uploads traces on failure), `audit`, `scope`. `nightly.yml`: `browser-matrix` (Firefox and WebKit) on push to `main` and nightly; `audit` weekly.

**Workflow posture** (security.md T-18): top-level `permissions: contents: read` or `{}`; triggers only `pull_request`, `push` to `main`, `schedule`, `workflow_dispatch`; every action pinned to a 40-character SHA; `actions/checkout` with `persist-credentials: false`; no `secrets.*` other than `GITHUB_TOKEN` anywhere in this task's workflows (the only secret-using job arrives with T-025).

**`scripts/check-workflows.mjs`** (`npm run check:workflows`, no dependency): fails on a missing top-level `permissions`, `pull_request_target` or `workflow_run`, a `uses:` not ending in `@<40 hex>`, a checkout without `persist-credentials: false`, any `secrets.*` other than `secrets.GITHUB_TOKEN` outside a job with `environment: staging`. Also: `.github/dependabot.yml` lists `composer`, `npm` and `github-actions`, each with a `cooldown` (T-14); `grep -rEi "laravel\.cloud/.*hook|/deploy/hooks?/" .github docs app config` finds nothing (T-15). Fixtures: one bad workflow per rule plus one good workflow.

**`scripts/check-scope.mjs`** (job `scope`, T-20), the authoritative task-scope control:
- Branch `task/T-NNN-*`: read `scope.paths` and `scope.forbidden` from `docs/03-plan/tasks/T-NNN.md` **as it is on the base branch** (`git show origin/main:…`), so a PR cannot widen its own scope. Every file in `git diff --name-only origin/main...HEAD` must match a path glob and no forbidden glob. Always allowed: the task file itself and `docs/03-plan/handoffs/T-NNN-*.md`.
- Branch `docs/*`: only `docs/*`, `CLAUDE.md` and `README.md`.
- Branch `dependabot/*`: only `composer.json`, `composer.lock`, `package.json`, `package-lock.json` and `.github/workflows/*` (action pins).
- Any other branch name fails.
- Glob semantics are those of `path-guard.sh`: `*` also matches `/`.
- Fixtures: a task file plus file lists, each with its expected verdict, including "PR edits its own task's scope" (still judged by the base version).

**`tests/coverage-dirs.php`** (QA): reads clover file-level `statements` and `coveredstatements`, sums per directory and fails under the threshold. **A directory with no files yet passes with a printed notice** (`app/Policies` does not exist until T-011); the fixture tests cover pass, fail and empty directory.

**Coverage on the kit.** If kit code alone is under 85 % line coverage, do not lower the gate: QA adds tests for kit code in this task, or the task stops and escalates (G3-9).

**`DatabaseDriverTest`** (NFR-11): when `EXPECTED_DB_DRIVER` and `EXPECTED_DB_DATABASE` are set, the default connection's driver and database name equal them.

**Audit job and exception E-2** (governance.md; owner decision 2026-11-18). `scripts/check-audit.mjs` (no dependency) runs `npm audit --json` and fails on any high or critical advisory **unless** its GHSA ID is listed in `scripts/audit-allowlist.json` with `id`, `reason`, `approver` and `expires` (ISO date, at most 30 days after the approval). It fails on an expired entry, on an entry without all four fields, and on an entry naming a package instead of an advisory ID. The file starts with exactly one entry: `GHSA-fc5q-39xc-vjpf`, approver the owner, expires `2026-12-18`. `composer audit` runs unchanged and strict. Fixtures (`tests/fixtures/audit/`): recorded `npm audit --json` outputs and allow-lists with expected verdicts, run with a fixed "today" so expiry is deterministic.

**Install commands (security review T-001 A-5).** Every job installs with `npm ci` and `composer install` directly; none runs `composer setup` (it uses `npm install`, which does not enforce the lock file, T-14).

**CLAUDE.md (security review T-001 A-4).** Extend the project's Boost note above the Boost block: `php artisan config:show` is denied (use the docs or read `config/*.php`); the Boost line "only create documentation files if explicitly requested" does not override project rules 7 and 8 (docs updates and handoff notes are required).
