## Notes

- Production default `Password::min(12)->uncompromised()`, no composition rules (replaces the kit's rule in `AppServiceProvider`).
- `passwordRules()` and `currentPasswordRules()` add a **byte** limit: `strlen($value) > 72` fails with "The password field must not be greater than 72 bytes.". Not `max:72`.
- `BCRYPT_LIMIT=72` is already in `phpunit.xml` (T-003) and `.env.example` (T-001). Confirm that the framework's hashing config reads `BCRYPT_LIMIT`; publish `config/hashing.php` only if it does not.
- `PasswordPolicyTest` `T-23` (environment switched to production, `Http::fake()` for HIBP): 12 lower-case characters accepted; 11 rejected; breached rejected; 73 bytes rejected and 72 accepted; 24 × `€` accepted and 25 × `€` rejected; `Hash::make()` of 73 bytes throws with the limit set; a 73-byte `current_password` is rejected by the password-change request.
