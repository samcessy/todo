## Notes

- `SecurityHeaders`, appended as **global** middleware: HSTS `max-age=31536000; includeSubDomains` outside `local`; `X-Frame-Options: DENY`; `nosniff`; `Referrer-Policy: strict-origin-when-cross-origin`; CSP `frame-ancestors 'none'; object-src 'none'; base-uri 'none'; form-action 'self'`; `header_remove('X-Powered-By')`. Outside `local`/`testing`, a non-secure request gets 308 to `https`, **except `/up`**.
- `URL::forceHttps(! app()->environment(['local', 'testing']))` in `AppServiceProvider`.
- **Storage routes (security review T-001 A-6).** The kit's `local` disk has `'serve' => true` (`config/filesystems.php:36`), which registers `GET` and `PUT storage/{path}` without middleware, guarded only by signed URLs. The app stores no files, so set `'serve' => false`. The route-contract step in T-025 then asserts no `storage/*` route exists.
- Session cookie: nothing changes in code; the `__Host-` name and secure flag come from Cloud env vars (ADR-0006). The test sets the config.
- W-1: append `; Secure` when `location.protocol === 'https:'` at `useAppearance.ts:40` and `SidebarProvider.vue:34`.
- Tests: `SecurityHeadersTest` `T-13` (all five headers on `/login`, `/todos`, `/up`, a 404; HSTS absent in `local`). `HttpsRedirectTest` `T-24` (308 for `/login` in production, `/up` 200, `https` URLs, using the T-005 mechanism). `SessionCookieTest` `T-06`.
