## Decisions made inside the task scope

- **Text "v-html" is not a directive (pass).** ADR-0003 says the script "walks the template AST and fails on
  `v-html`" and on `v-bind`/`:` with argument `innerHTML`/`outerHTML`. Text in an HTML comment
  (`COMMENT` node), inside an interpolated string literal (`INTERPOLATION` node) or in a text node never
  produces a `DIRECTIVE` prop, so nothing raw is rendered and NFR-03 ("no raw HTML from user content") is
  not at risk. Failing it would mean a naive text grep, which the ADR deliberately replaced with an AST walk.
  The fixture also has the string `v-html` in its `<script setup>` block: the script-side scan only targets
  `innerHTML`, `outerHTML`, `insertAdjacentHTML` and `document.write`, so it must not fire. The fixture avoids
  those four words entirely so the verdict does not depend on whether the grep also runs over template text.
- **Object-spread fixture (extra, fail).** ADR-0003 names `v-bind="{ innerHTML: x }"` as a known limitation
  that the script-side grep catches "if it is written literally in the template". The fixture pins that
  promise: the implementation must grep the template source (or inspect the `v-bind` object expression)
  for `innerHTML`/`outerHTML`, not only `<script>` blocks.
- **Extra fixtures:** `ts-outerhtml.ts` (fail) covers the fourth script-side token; `safe-ts-text-content.ts`
  (pass) guards against a `.ts` scan that fails everything.
- **Allow-list is matched on exact file + exact expression** (fixtures 4 to 7): right file/wrong expression
  and wrong file/right expression both fail; a file with the allowed binding plus another `v-html` fails as a
  whole.
- `v-html-in-component.vue` puts the directive inside a `v-if` branch so a top-level-only walk fails the test.
- Fixtures were formatted with the project formatter (`vp check --fix tests/fixtures/raw-html`); only
  `expected.json` was reflowed. `vp check` on the folder is clean.

### Decisions
- **B-1 in fixture mode.** Fixture mode already scans every fixture, whatever its extension. That is why the
  `.js`/`.tsx`/`.jsx`/`.mts` entries are already `ok`: the sinks are caught once the file is read. The bug is the
  repo-mode extension filter (`/\.(vue|ts)$/`), which fixture mode never runs. The contract for the fix:
  - Repo mode scans `resources/js/**` files that match `/\.(vue|[cm]?[jt]sx?)$/`. `.vue` gets the SFC walk;
    the rest get the script token scan.
  - Fixture mode applies **the same extension filter to each entry's `as` path**. An `as` that is not a
    bundled source extension is not scanned, so the result is `pass`. That makes the repo-mode filter
    testable: the four B-1 entries must stay `fail` (the filter includes them). The `.vue.bak` entry must
    turn `pass` (the filter is applied, and is not a match-everything). It holds a `:innerHTML` binding so
    that today's unfiltered fixture mode reports it as `fail`. That is the red B-1 signal.
  - `.vue.bak` and other unknown extensions are **not bundled by Vite**, so they cannot be an XSS vector, and
    I chose `pass`. The reviewer's stronger option (fail on any extension under `resources/js` that is not
    known safe) remains open. See the task `## Questions`.
- **DOMParser is a fail.** `parseFromString(x, 'text/html')` does not render on its own. In practice its nodes
  are adopted into the live document, which brings back the `onerror`/`onload` handler vector, and an
  app that only renders text never needs it. A false positive costs one allow-list review. A false negative is
  stored XSS.
- **Dynamic `v-bind` arguments are a fail, whatever the value.** `:[attr]` cannot be resolved statically, and
  the kit has none. If a legitimate dynamic arg is ever needed, it must be rewritten as static bindings or
  allow-listed by file and expression through the owner (the same route as the QR code).
- **`<template src>` and non-HTML `lang` are a fail.** There is no parsed tree, so the gate cannot verify the
  template, and it fails closed. The `src` target `./todo-card.html` deliberately does not exist: the verdict
  must not depend on reading it.
- `safe-iframe-src.vue` is a guard and is `ok` today. It must stay `pass` after the `srcdoc` token is added
  (no over-broad `src`/`iframe` match).
- Out of scope here: A-5 (generated-dir skip) and A-6 (fixture dirs in the T-18 protected list), plus
  interpolation token scanning (A-4 option). No fixtures were added for those.
