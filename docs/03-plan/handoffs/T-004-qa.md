## Decisions made inside the task scope

- **Text "v-html" is not a directive (pass).** ADR-0003 says the script "walks the template AST and fails on
  `v-html`" and on `v-bind`/`:` with argument `innerHTML`/`outerHTML`. Text in an HTML comment
  (`COMMENT` node), inside an interpolated string literal (`INTERPOLATION` node) or in a text node never
  produces a `DIRECTIVE` prop, so nothing raw is rendered and NFR-03 ("no raw HTML from user content") is
  not at risk. Failing it would mean a naive text grep, which the ADR deliberately replaced with an AST walk.
  The fixture also has the string `v-html` in its `<script setup>` block: the script-side scan only targets
  `innerHTML`, `outerHTML`, `insertAdjacentHTML` and `document.write`, so it must not fire. The fixture avoids
  those four words entirely so the verdict does not depend on whether the grep also runs over template text.
- **Object-spread fixture (extra, fail).** ADR-0003 names `v-bind="{ innerHTML: x }"` as a known limitation
  that the script-side grep catches "if it is written literally in the template". The fixture pins that
  promise: the implementation must grep the template source (or inspect the `v-bind` object expression)
  for `innerHTML`/`outerHTML`, not only `<script>` blocks.
- **Extra fixtures:** `ts-outerhtml.ts` (fail) covers the fourth script-side token; `safe-ts-text-content.ts`
  (pass) guards against a `.ts` scan that fails everything.
- **Allow-list is matched on exact file + exact expression** (fixtures 4 to 7): right file/wrong expression
  and wrong file/right expression both fail; a file with the allowed binding plus another `v-html` fails as a
  whole.
- `v-html-in-component.vue` puts the directive inside a `v-if` branch so a top-level-only walk fails the test.
- Fixtures were formatted with the project formatter (`vp check --fix tests/fixtures/raw-html`); only
  `expected.json` was reflowed. `vp check` on the folder is clean.
