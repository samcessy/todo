## Security follow-up: A-1, widened T-12 logging ban (2026-11-18)

Source: `docs/03-plan/handoffs/T-004-security.md` A-1. Changed: `tests/Arch/ArchTest.php` only.

### What T-12 now bans in `App`
1. Arch rule `T-12 nothing in App uses the Log facade, logger(), info(), logs(), PSR-3, Illuminate\Log, error_log() or syslog()`:
   `Illuminate\Support\Facades\Log`, `Log`, `logger`, `info`, `logs`, `Psr\Log\LoggerInterface`, `Psr\Log`
   (prefix), `Illuminate\Log` (prefix: `LogManager`, `Logger`), `error_log`, `syslog`.
2. New test `T-12 nothing in App references the global Log alias (\Log or use Log)`. It tokenizes every
   `app/**/*.php` file (`PhpToken`) and fails on a fully qualified `\Log` or a `use Log;` import. The match
   is case-insensitive.

### Why a separate test for the `Log` alias
Probing showed that `->not->toUse('Log')` **does not detect** `\Log::info()`. The alias exists only after the
Laravel app boots (AliasLoader), and arch tests don't boot it. The plugin's `ObjectsRepository::allByNamespace('Log')`
therefore finds no class. It only prefix-matches the user-defined functions `logger`/`logs` (case-insensitive
`str_starts_with`). The original rule's `'Log'` entry never covered the alias. I kept it in the list so the
diff does not look like a weakening, and the tokenizer test now covers the alias.

### Probe (throwaway, deleted, not committed)
`app/ZzProbes/*.php` held one class per target. `tests/Arch/ZzProbeTest.php` asserted `toUse(target)` and
`not->toUse(target)` for each class. Results (worktree-rooted harness, see below):

| Probe class (usage) | Target | `toUse` detected | `not->toUse` fails |
|---|---|---|---|
| `Log::info()` via `use Illuminate\Support\Facades\Log` | `Illuminate\Support\Facades\Log` | yes | yes |
| `\Log::info()` | `Log` | **no** | **no**: covered by the tokenizer test (hit at `AliasProbe.php:9`) |
| `use Log; Log::info()` | `Log` | n/a | tokenizer test hit at `AliasImportProbe.php:5` |
| `logger('x')` | `logger` | yes | yes |
| `info('x')` | `info` | yes | yes |
| `logs()->info()` | `logs` | yes | yes |
| ctor-injected `Psr\Log\LoggerInterface` | `Psr\Log\LoggerInterface` / `Psr\Log` | yes | yes / yes |
| ctor-injected `Illuminate\Log\LogManager` | `Illuminate\Log` | yes | yes |
| `error_log('x')` | `error_log` | yes | yes |
| `syslog(LOG_INFO, 'x')` | `syslog` | yes | yes |
| control: `SyslogProbe` vs `logger` | `not->toUse('logger')` | passes (no false positive) | |

With the probes present, both T-12 tests failed: arch (`Expecting 'App' not to use 'syslog'`) and tokenizer
(2 hits). After the probes were deleted, both pass: 2 tests, 21 assertions. `git status` was clean apart from
`ArchTest.php` before the commit.

Not statically catchable (review checklist): `app('log')`, `resolve('log')`, `app(LoggerInterface::class)` by
string.

  classmap). In this environment, PHP tests and arch scans run in a worktree would exercise the **main

    `Trait "Symfony\Component\DependencyInjection\Compiler\PriorityTaggedServiceTrait" not found` in
    `vendor/symfony/serializer/.../SerializerPass.php`. These `toBeUsed`-style scans load every vendor class.
    The shared vendor now contains `symfony/serializer` (dir dated today, 14:04) without
    `symfony/dependency-injection`, so it no longer matches this branch's `composer.lock`. It is unrelated to

- So the "49+ passing" target **could not be confirmed**: 46 of 50 tests are verifiable, and the 4 preset or
