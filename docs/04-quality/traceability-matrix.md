# Traceability matrix

**Status:** Draft, revised after the G2 re-check (2026-11-17, QA engineer agent). It replaces the 2026-11-16 draft. No tests exist yet, so every row is **Planned**.
**Source of truth after implementation:** grep `(US-\d{2}|CC)\.AC\d+` in `tests/` and in the frontend unit tests under `resources/js/` (`coding-standards.md` §4). Non-AC rows are found by their `T-xx`, `NFR-xx` or `FR-xx` prefix. This file is regenerated from those greps in verification mode.
**Design inputs:** `contracts.md` (§1.1.1 status codes, §2 validation, §3 filter and query budget, §5.3 overdue, §6.1 UI contract U-01 to U-23 and focus targets F-a to F-l, §7 trace), `security.md` §2 and §4, ADR-0003, `governance.md` exception E-1.

Conventions:
- Every test name starts with its ID: an AC ID, threat ID (`T-xx`), NFR ID (`NFR-xx`) or FR ID (`FR-xx`). A test may name several IDs (`coding-standards.md` §4).
- **Status codes (contracts §1.1.1):** write-route tests send `X-Inertia: true` through the `inertia()` helper in `tests/Pest.php`, and assert the exact status. POST success or validation failure gives 302. PATCH or DELETE success or validation failure gives 303. The 419 handler always gives 302. Guest, 403, 404 and 429 tests may omit the header. The T-001 spike confirms each cell before the status assertions are written.
- Toasts are asserted with `assertInertiaFlash('toast', [...])`. Time is frozen with `travelTo()` **before** any model is created. Titles are explicit wherever order or text is asserted (data-model §4).
- Browser tests locate elements by the role and accessible name in contracts §6.1 (`U-xx`). They assert focus by reading the id of `document.activeElement` (`F-x`). The plugin API for that is a T-001 spike item (ADR-0003).
- **E-1** (`governance.md`): `tests/Feature/DashboardTest.php` is deleted and replaced 1:1 by the two `IndexTest` rows marked E-1. Six kit assertions are retargeted to `todos.index`. All of this happens in one QA task with `human_approval_required: [E-1]`. E-1 is the only test deletion verification mode accepts.

Layers:
- **Feature**: Pest feature test (`test-sqlite` and `test-pgsql` jobs).
- **Unit**: Pest unit test (pure PHP).
- **Frontend unit**: Vitest through `vp test run` (`npm run test`, CI `js-unit`).
- **Browser**: Pest browser plugin (`browser-chromium` on PRs; Firefox and WebKit on `main` and nightly).
- **Kit feature**: an edited starter-kit Pest test.
- **CI check**: a non-Pest CI job or script with fixture tests.
